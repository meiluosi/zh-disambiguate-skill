# 真实文本试用

用 8 段开源 MCP server 里真实存在的中文工具描述试用 skill。来源、提交号和协议见 [`sources.md`](sources.md)。

**这不是人类评测。**下面的「读者」是 Claude 扮演的中文开发者，只有一个人，只有 8 段。它的用处是发现问题，不是证明 skill 有效。真人评测还没做。

## 做法

1. 子代理按 SKILL.md 改写 8 段（`items/*/rewrite.md`）。这些文本没有作者可问，所以子代理只能保留含糊处，把问题写在「保留未改：」一行里。
2. 我随机打乱 A/B，先按字母记下哪个更好用、再揭晓答案（[`review-claude-as-dev.json`](review-claude-as-dev.json)）。盲评其实很弱：改写稿末尾的「保留未改：」和空格风格一眼能认出来。判断标准是：把它放进真实 agent 的工具列表，哪个更好用。
3. 对每一对跑 `zh-lint.py` 和 rewrite-fidelity。

## 结果

| 条目 | 我的选择 | 原因 |
|---|---|---|
| 01 钉钉发文本 | 改写稿（弱） | 「最大用户列表长度：100」改成「最多包含 100 个 userId」，更顺。 |
| 02 钉钉发 markdown | 改写稿（弱） | 同上。 |
| 03 钉钉撤回 | 改写稿（弱） | 「撤回给员工的消息」改成「撤回发给员工的消息」，修了一个小语病。 |
| 04 钉钉员工数 | 平局 | 两者都清楚。 |
| 05 高德 IP 定位 | **改写稿（明显）** | 原文「IP 定位根据用户输入的 IP 地址，定位……」是病句，改写稿断句后能读。 |
| 06 高德步行 | **原文** | 改写稿正文里留了「（是否含 100 km 待确认）」，会被模型读到。 |
| 07 百度搜索 | **原文（弱）** | 原文已经清楚、更短。改写稿更长，还把「而不是重新搜索」改成了「不得重新搜索」。 |
| 08 百度 fetch_url | 平局 | 没有实质区别。 |

改写稿 4 胜、原文 2 胜、平局 2。这个比例不能当结论。

## 发现了什么

**1. 价值主要在「保留未改」的提问，不在改写后的文本。**改写稿本身多数只是断句、加空格、修标点。真正有用的是子代理指出的、原文没有答案的问题：

- 01、02：「2048 字节」按什么编码算，一个汉字占几个字节？
- 05：没有列出参数名；返回的位置精确到哪一级？
- 06：「100 km 以内」是直线距离还是步行路线距离？超出后返回什么？坐标系是什么？
- 07、08：「请谨慎使用」「需要详细内容」没有可判定的条件。

这些问题只有作者能回答。skill 做对了的地方是没有替作者编答案。

**2. 一个 skill 自己的缺陷：占位符泄漏。**06 号改写稿的正文里有「（是否含 100 km 待确认）」。原因是第一版 SKILL.md 本身建议这样写。已改成：正文不放任何占位符，疑问只放在「保留未改：」一行，并注明这一行粘贴前要删掉。

**3. 一个 skill 没发现的问题：两个工具的描述一字不差。**01 和 02 是两个不同的工具（发文本、发 markdown），描述都是「企业用户发送消息」，模型无法按描述选工具。逐段改写发现不了这一点，因为每一段单独看都没问题。已在 SKILL.md 加一条：改写一组工具描述时对比同组的描述。这条没有单独验证过。

**4. rewrite-fidelity 在真实文本上抓到一个真问题。**07 号里「使用 fetch_url，**而不是**重新搜索」被改成「**不得**重新搜索」，建议变成了禁令（`modal.prohibit` 1 → 2）。skill 自己的「保留情态强度」规则没有拦住这一处，说明改写后跑一遍保真检查是必要的。

**5. rewrite-fidelity 在真实文本上暴露了一个 bug。**真实中文几乎不在汉字和数字之间加空格（「不超过2048个字节」）。Python 的 `\w` 把汉字也算进去，于是这种写法的数字没被提取，改写稿里加了空格的 `2048` 就被当成「新增」，报了误报。已修复（字面量的正则只认 ASCII），并加了测试。手写的示例里没有这种写法，所以之前的 30 条自测都没发现。

**6. zh-lint 在这 8 段上几乎沉默。**只有 06 号报了 1 条（「100km 以内」的边界）。大部分问题是语义上的，不是形式上的。这与第二轮评测的观察一致：规则能数的问题只是一小部分。

## 局限

- 8 段，3 个仓库，不具统计意义。选这 3 个仓库是因为协议允许引用，不是随机抽样。
- 读者是 Claude，不是人。
- 子代理改写时没有作者可问，所以这里没有测「作者回答问题之后改写得怎么样」，那部分在 [`../agreement`](../agreement/README.md) 的第二轮。
- 原文里的 emoji 和「⚠️」没有处理。
