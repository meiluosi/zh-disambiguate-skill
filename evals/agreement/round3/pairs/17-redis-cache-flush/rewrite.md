缓存数据脏了、需要清除时，不得直接执行 `FLUSHALL`。`FLUSHALL` 会把 session 一起清除，所有人都要重新登录。

按以下步骤清除：

1. 执行 `redis-cli --scan --pattern '<pattern>'`，找出要清除的 key。
2. 用 `UNLINK` 分批清除这些 key，每批约 500 个。批与批之间执行 `sleep 1`。
3. 清除完成后，在主库监控面板上观察数据库 CPU。原因：缓存清除后，请求会穿透到数据库。
4. 如果数据库 CPU 持续 1 分钟超过 70%，暂停清除。等 CPU 回到 50% 以下，再继续清除。

`<pattern>` 的规则：

- 你必须按实际受影响的前缀填写 pattern，例如 `product:*`。`product:*` 只是例子。
- 任何前缀的 key 脏了，都按上面的步骤清除。
- pattern 不得匹配到 session 前缀 `sess:*` 的 key。

保留未改：（1）数据库 CPU 是每批 `UNLINK` 之后看，还是全部清除完成后才看？如果是全部完成后才看，「暂停清除」和「继续清除」指的是什么操作？（2）「回到 50% 以下」是否包含正好 50%？
