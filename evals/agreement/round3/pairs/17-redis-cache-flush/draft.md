缓存数据脏了、需要清除时，不得直接执行 `FLUSHALL`。`FLUSHALL` 会把 session 一起清除，所有人都要重新登录。

按以下步骤清除：

1. 执行 `redis-cli --scan --pattern 'product:*'`，找出要清除的 key。
2. 用 `UNLINK` 分批清除这些 key，每批约 500 个。
3. 清除完成后，观察数据库 CPU。
4. 如果数据库 CPU 超过 70%，先停止清除。等 CPU 降下来，再继续清除。

保留未改：（1）「数据库 CPU」是 Redis 实例的 CPU，还是后端数据库的 CPU？（2）CPU 是每批 `UNLINK` 之后看，还是全部清除完成后才看？如果是全部完成后才看，「停手」和「继续」指的是什么操作？（3）CPU 降到多少可以继续？（4）脏数据只会在 `product:*` 下吗？其他前缀的 key 脏了时，是否同样处理？
