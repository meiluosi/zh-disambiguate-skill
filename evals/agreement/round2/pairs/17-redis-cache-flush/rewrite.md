缓存数据脏了时，按以下步骤清理缓存。

「脏了」指缓存里的数据和数据库不一致，并且短时间内不会自愈。例如：价格改错后已经回滚。TTL 快到期的正常过期不算脏了。

1. 在预发环境以外，不得执行 `FLUSHALL` 或 `FLUSHDB`。`FLUSHALL` 会把 session 一起清掉，所有用户都必须重新登录。
2. 执行 `redis-cli --scan --pattern '<前缀>*'`，找出受影响的 key。
3. 把 `<前缀>` 换成实际受影响的前缀。`product:*` 只是示例。
4. pattern 不得匹配到 session 前缀 `sess:*`。
5. 分批对找到的 key 执行 `UNLINK`，每批约 500 个。
6. 每批之间执行 `sleep 1`。
7. 清理期间，在主库监控面板上观察数据库 CPU。
8. 数据库 CPU 持续 1 分钟超过 70% 时，暂停清理。
9. 数据库 CPU 回到 50% 以下后，再继续清理。

暂停的原因：缓存被清掉后，请求会穿透到数据库。
