如果 `checkout-api` 的 CPU 连续在 80% 以上约 5 分钟或更久（不是瞬时尖峰），可以先按以下步骤处理：

1. 手动把 `replicas` 从 4 调到 8。命令：`kubectl scale deploy/checkout-api --replicas=8`。HPA 的上限是 12。手动调整时，`replicas` 不得超过 12。
2. 调整后等约 5 分钟，检查负载有没有下降。判断负载是否下降，主要看 CPU 是否回落到 80% 以下。
3. 如果负载没有下降，不得再做任何手动扩容。找负责下游服务的同事排查是不是下游服务慢。

保留未改：（1）「80% 以上」和「回落到 80% 以下」是否包含正好 80%？（2）CPU 使用率按什么计算：所有 Pod 的平均值还是单个 Pod？相对 CPU request 还是 CPU limit？（3）当前 `replicas` 不是 4 时（例如 HPA 已经扩到 6），还调到 8 吗？（4）除了第 3 步的情况，什么情况下可以把 `replicas` 调到超过 8（最多 12）？
