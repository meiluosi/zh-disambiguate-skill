缓存数据脏了、需要清理时，按以下步骤处理：

1. 不得执行 `FLUSHALL`。`FLUSHALL` 会把 session 一起清掉，所有用户都必须重新登录。
2. 执行 `redis-cli --scan --pattern 'product:*'`，找出要清理的 key。
3. 分批执行 `UNLINK`，清理这些 key。每批 500 个左右。
4. 清完后，观察数据库 CPU。
5. 如果数据库 CPU 超过 70%，先暂停 `UNLINK`。等数据库 CPU 降下来后，再继续。

保留未改：（1）「数据库 CPU」是指 Redis 实例的 CPU，还是后端数据库的 CPU？在哪里观察？（2）「清完」是指每批清完后观察，还是全部 key 清完后观察？（3）数据库 CPU 降到多少以下才能继续？（4）`product:*` 是固定的匹配模式，还是只是一个例子，要按脏数据所在的前缀替换？
